# 项目背景与动机

## Why bilidown

B 站是我日常使用最多的软件，上面有丰富的视频资源和 良好的社区文化，但是其特殊的视频格式和水印设置让我在下载和备份时遇到不少麻烦。还有一件事情是有些时候我也想让 ai 帮我完成下载的工作，所以脚本化，命令行是我的核心需求。开源社区其实已经有不少针对 B 站的插件或者各种下载工具，比如我现在手机端使用的 Piliplus，网页端使用的 BewlyCat，但是都没有解决我下载器的需求。目前 github 上现有的命令行下载器中，一部分已停止维护（例如曾经的事实标准 BBDown 已归档（用 C#写的）、Rust 写的 bili-cli-rs 多年未更新（已经因为接口改变和风控不能用了）），另一部分是带图形界面的桌面应用，不便于脚本化和批量处理。

因此我想实现一个**纯命令行、可脚本化**的下载器：单个二进制即可运行，方便批量下载与资料备份，并把 WBI 签名、并发分片、断点续传这些"现代 B 站接口该有的能力"做扎实。

## Why Rust

这个项目是典型的"网络 I/O 密集 + 需要管理大量临时资源"的程序，Rust 的几个特性正好对症：

1. 编译后足够轻量：Rust 编译后的二进制文件体积小，运行时不依赖虚拟机或解释器，适合在各种环境下部署。
2. 内存安全和高性能：Rust 的所有权系统和借用检查器可以在编译期捕获大部分内存错误，避免了运行时的内存泄漏和悬空指针问题，同时 Rust 的性能强大，适合处理大量数据和高并发任务，对于视频下载这种高并发的场景比较合适
3. 单纯为了水个大作业（顺手的事）

## 目标与范围

- **目标用户**：希望在命令行里批量下载、备份 B 站内容的用户（包括我自己）。
- **核心范围**：登录、搜索、解析视频/番剧元数据、并发下载音视频、合并、附加资源（封面/字幕/弹幕）、配置与归档。
